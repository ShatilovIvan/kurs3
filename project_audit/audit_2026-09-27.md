## 6. Разбор скиллов по одному

Дополнение к находке MED 4. Проверены тексты скиллов, а не только описания.

### Сторонние скиллы

**6.1. `enterprise-architecture` — удалить (или хотя бы исправить README).**
- Собственное описание скилла: «Do NOT trigger for … ER schema design, code-level UML or sequence diagrams». SE требует диаграммы прецедентов, последовательности, классов и деятельности, DBMS — ER в IDEF1X. README назначает скилл на SE и OOAD, то есть противоречит самому скиллу.
- Нотации скилла — C4, ArchiMate, TOGAF, arc42. В материалах курсов их нет (там UML в Rational Rose / Visual Paradigm, IDEF0, EPC). По правилу 5 это выход за курс, на защите спросят, откуда он взялся.
- Большой объём: 174 строки, 7 справочников, 2 скрипта. Всё это попадает в контекст ради того, что лабам не нужно.

**6.2. `software-architecture` — отложить до появления материалов OOAD.**
- Содержание — Clean Architecture, DI, паттерны на примерах бэкенд-кода (`UserService`, PostgreSQL, платёжные провайдеры). ООАП в ОмГТУ, судя по UML-пособиям в SE, — это UML-модели в Rose, а не рефакторинг кода.
- 479 строк общих принципов без привязки к предметной области курса.
- Формат ADR дублирует блок «Решения» в `log.md`.

**6.3. `modern-web-app-architecture` — оставить с оговоркой в README.**
- Сильный уклон в React: Next.js, React Query, Zustand упоминаются 17 раз. WebDev ЛР 2 оставляет выбор фреймворка студенту, а скилл незаметно подталкивает к Next.js с SSR/ISR, хотя задание просит просто SPA с роутером.
- Нет того, что реально нужно в курсе: PWA и service worker (ЛР 5), сервисы на axios (ЛР 3), io-ts / fp-ts (ЛР 4). Слово «offline» встречается один раз.
- Core Web Vitals, бюджет бандла, ISR задание не требует: риск переусложнить решение и получить лишние вопросы на защите.
- Полезен только на ЛР 2–3 (структура SPA, состояние).

**6.4. `non-functional-requirements-elicitation` — оставить.**
- Нужен в SE для РГР, раздел 1: План РГР, L44–45 — «не забыть системные и нефункциональные требования».
- Минус: приучает к промышленным числам (p95 ≤ 400 мс, RTO/RPO). Для учебной РГР их придётся придумывать, а это конфликт с правилом 8 «не выдумывать». При использовании помечать числа как целевые / условные.

**6.5. `ambiguity-detection-in-requirements` — оставить.**
- Подходит для разбора самих заданий: нумерация ЛР в SE, нефиксированная «принятая нотация» в DBMS, не указанный фреймворк в WebDev. Хорошо дополняет пункт «Ambiguity» скептика в режиме `plan`.
- Минус: написан под проверку PRD перед QA, на задание ЛР сам не сработает — вызывать явно.

**6.6. `requirements-gap-analysis` — удалить.**
- «Как есть / как надо» формально пересекается с AS-IS / TO-BE у Бояркина (ЛР 1 и 4), но методичка задаёт свой способ (IDEF0, Business Studio). Скилл даст другую структуру, чем ждёт преподаватель.
- В текущем BPMN-задании (описание по шаблону + 3 модели) анализа разрывов нет.

**6.7. `stakeholder-interview-guide` — удалить.**
- README пишет «ProgPractice (МЕМО)», но МЕМО — уже готовая запись встречи с «заказчиком», проводить интервью не с кем.
- Постановку ML-задачи курс требует по CRISP-DM (Лекция 1: задача, объект, образ результата), а не через банк вопросов стейкхолдерам.

**6.8. `mvp-scope-cutting` — удалить.**
- В лабах объём задан методичкой: всё из критериев обязательно, урезать нельзя.
- MoSCoW / RICE в курсах нет. Если агент последует скиллу, он может пометить требования ЛР как «Won't» — прямой риск потерять баллы.

**6.9. `estimation-from-requirements` — удалить.**
- Оценки трудоёмкости нет ни в одном задании; сроки задаёт методика.
- Для планирования семестра достаточно «Следующего шага» в `progress.md`.

**Общее по сторонним скиллам.** Все на английском и под промышленный SDLC (PRD, QA, спринты), а документы курсов — русские методички ОмГТУ. Скиллы срабатывают автоматически по описанию: чем больше лишних, тем выше шанс, что агент возьмёт их подход вместо методички. **6.11. `debug` — оставить, поправить.**
- Требует «написать новый падающий тест». В ноутбуках, HTML и SQL тестов нет — нужна замена: минимальная ячейка или скрипт воспроизведения.
- `debugger` сам правит решение, и студент может не понять фикс. Скилл только предлагает объяснить причину; нужно требовать запись причины в `log.md` — иначе вопрос на защите без ответа.
- Та же проблема с frontmatter, что у скептика.

**6.12. `plain` — оставить как есть.** Маленький, ручной, вызывается только по `/plain`, полезен при подготовке к защите.
