## Требования и критерии

### BPMN-задание (EduCab #4)
Что сдать (по тексту задания): установить ELMA 365 или другое ПО для BPMN 2.0; **текстовое описание по шаблону + модели 3 бизнес-процессов** для предметной области из индивидуального варианта (варианты — Boyarkin, стр. 33–38). Уроки BPMN 1–8 — только по внешней ссылке elma-bpm.ru (в материалах нет).

Поля шаблона (Шаблон описания бизнес-процесса.docx, весь документ) — для каждого процесса:
1. Название: «Описание бизнес-процесса …».
2. **Цель**.
3. **Перечень действий** — нумерованный, у каждого шага указан срок/тайминг («мгновенно», «в течение 15 минут»…); развилки как подпункты (5.1, 5.2, 5.3: «если… — …»).
4. **Реализация процесса** — общая длительность (в образце 4–5 часов).
5. **Сопровождение процесса** — каналы обмена информацией/документами, контроль.
6. **Результат процесса** — варианты исхода (в образце 2).
7. **Ресурсы**.
8. **Исполнитель**.
9. **Показатели эффективности процесса** (KPI).

### ЛР 3 — диаграмма прецедентов (Лабораторная работа 1-2 (2).pdf)
- Инструмент: Visual Paradigm for UML Community Edition (стр. 1).
- Задание (стр. 8): построить диаграмму прецедентов по варианту. Отчёт — **MS Word**: пошаговое описание построения + скриншоты результатов.
- Элементы, отработанные в примере (стр. 4–8): System (граница системы), актёры, ассоциации **с кратностью** (стр. 6–7), отношения **extend** (стр. 7) и **include** (стр. 8).
- Варианты (стр. 9): 1 Отдел кадров, 2 Агентство аренды, 3 Аптека, 4 Ателье, 5 Аэропорт, 6 Библиотека, 7 Кинотеатр, 8 Поликлиника, 9 Автосалон, 10 Таксопарк.
- Контрольные вопросы (стр. 9): назначение Use Case диаграммы; её основные элементы; как создать её в VP.

### РГР (План РГР.docx; образец — Пример РГР 2.docx)
Тема на титуле: «Проектирование … средствами UML» (Титульный_лист_РГР_ФИТ). Разделы по Плану РГР:
1. **Постановка задачи**: краткое описание предметной области; описание проблемы (текстом или таблицей «Проблема / затрагивает / её следствием является / успешное решение»); описание пользователей (таблица «Типичный представитель / Описание / Тип / Ответственности / Критерий успеха»); ключевые потребности. **ВАЖНО: не забыть системные и нефункциональные требования** (План, L44–45).
2. **Глоссарий** — таблица «Термин | Значение» (L46–91).
3. **Акторы и варианты использования**: таблица акторов (актор | краткое описание); таблица прецедентов (основной актор | наименование | формулировка); диаграмма(ы) прецедентов с анализом обобщения/extend/include; **реестр вариантов использования** (код | актор | наименование | формулировка); **описание 1–2 прецедентов**: краткое описание, основной поток, подчинённые потоки, альтернативные потоки, предусловия, постусловия (L92–240).
4. **Диаграммы взаимодействия** (последовательности и кооперации) — минимум для одного прецедента на основе его сценария; **обязательно пояснять текстом, «нельзя вставлять просто картинки»** (L241–249).
5. **Диаграммы деятельности** — для любых процессов (L250).
6. **Диаграмма классов** — описать классы, их вид, взаимодействие, атрибуты и операции (L251–253).
+ Введение, Заключение, Список источников (так в обоих примерах). Пример РГР 2 дополнительно содержит 1.3 «Требования системы» и диаграмму пакетов (рис. 6).

Требования к оформлению — **только в пособие_UML (для отчёта по его практикуму, не для РГР явно)**, L79–89: 20–25 стр. А4, Word, поля Л30/П10/В20/Н25 мм, Times New Roman 14, абзац 10 мм, интервал 1,5, каждый раздел с новой страницы, номер страницы внизу по центру. Требования к оформлению РГР от преподавателя: **не найдено**.
