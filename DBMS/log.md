## 2026-09-30 06:23 — ЛР 2: исправлена ошибка запуска 01_create_database.sql в pgAdmin
- Сделано: из `solution/lab2/01_create_database.sql` убран `COMMENT ON DATABASE` — теперь в файле одна команда `CREATE DATABASE`; комментарий к базе перенесён в начало `solution/lab2/02_create_tables.sql`. Обновлены `solution/lab2/README.md` (раздел «Запуск в pgAdmin») и `solution/lab2/build_report.py` (пояснение в разделе 1 отчёта), `report.docx` пересобран.
- Результат: у студента в pgAdmin при запуске файла целиком — «ERROR: CREATE DATABASE не может выполняться внутри блока транзакции», SQL state 25001. Ошибка воспроизведена на PostgreSQL 15: старая версия файла, переданная одной строкой запроса (как это делает pgAdmin), даёт «CREATE DATABASE cannot run inside a transaction block». Новая версия так же одной строкой: `CREATE DATABASE`, затем `02_create_tables.sql` одной строкой — без ошибок, комментарий у базы есть; вывод `03_check.sql` совпадает с `check_output.txt` (отличается только порядок строки `DO` и сообщений NOTICE — это чередование stdout и stderr).
- Решения: причина — pgAdmin отправляет несколько команд одним запросом, и PostgreSQL выполняет его как одну неявную транзакцию, а `CREATE DATABASE` в транзакции запрещён. `COMMENT ON DATABASE` можно выполнить из любой базы, поэтому он перенесён в скрипт, который запускается на `formula1`.
- Дальше: студент запускает три скрипта в своём pgAdmin, сверяет типы, вписывает ФИО, пересобирает отчёт; затем `/check-lab DBMS 2 solution`.
